# 基础编码规则

## 目录与依赖

提炼自源项目的职责划分，目录名可以适配目标仓库：

| 位置 | 职责 | 约束 |
|---|---|---|
| `web/api/` | 请求解析、校验、调用用例、响应转换 | 复杂业务步骤下沉到业务单元 |
| `<business>_process/main_graph.py` | 节点创建、注册、连接、路由和运行入口 | 不直接实现外部 SDK 调用 |
| `<business>_process/nodes/` | 每个文件一个主要业务阶段 | 使用状态和适配器，不反向依赖 Web 入口 |
| `<business>_process/state.py` | 跨节点数据契约 | 字段有产生方、消费方与可用时机 |
| `config/` | 配置模型、配置加载和 Prompt | 参数按领域分组，校验缺失值 |
| `utils/` 或项目现有 `adapters/` | 模型、存储、HTTP 等外部能力 | 按具体能力命名；避免万能工具文件 |
| `tools/` | 日志和开发辅助工具 | 可执行工具有独立入口 |
| 项目测试目录 | 可重复的行为验证 | 演示脚本不计作通过的自动化测试 |

已有项目采用其他分层时保留其结构，只映射职责。

## 命名、类型与导入

- Python 标识使用英文；函数以动作命名，如 `generate_embeddings`、`get_recent_messages`。布尔值表达可判断状态，如 `is_stream`、`is_pdf_read_enabled`。
- 遵循项目格式化配置和 PEP 8；标准库、第三方、本地导入分组。显式导入符号，新增代码避免 `import *`。
- 公共函数与业务边界写参数及返回类型。采用 Python 版本支持的 `list[T]`、`dict[K, V]` 和联合类型；不因风格改动提高项目最低版本。
- 默认值为 `None` 的参数，其类型也包含 `None`。请求模型的类型、默认值、必填性、字段说明一致。
- 列表中的业务对象使用明确结构；`Any` 限于外部边界尚未解析的值。`TypedDict` 描述形状，运行时校验仍由入口或显式校验完成。
- 对外错误结构、函数返回类型和正常/降级分支保持一致。

## 方法组织与中文注释

- 类 docstring 说明业务职责；公共方法 docstring 说明用途、输入前提、输出及重要异常/副作用。
- `process()` 或用例入口应能直接看懂主步骤。较复杂过程按“校验 → 数据准备 → 核心处理 → 结果组装”拆分，只保留实际需要的步骤。
- `_step_1_*` 是源项目的可选可读性惯例；普通私有函数优先语义名称。编号变化不应成为不必要的公共接口变更。
- 源规范将超过 50 行列为拆分信号。提炼后把它用于检查职责与分支复杂度，不作为机械切分或凑行数要求。
- 注释解释业务原因、算法假设、字段含义及复杂索引边界；步骤编号与实际调用顺序一致。删除过时注释，不新增逐行语法讲解、长篇注释掉的旧实现。

## 配置与资源

- 环境参数集中加载为领域配置对象；端点、路径、模型、批大小和超时从配置获得。校验必需项、数值范围及布尔转换，错误指出字段名而不泄露值。
- 不复制开发机绝对路径、凭据或原项目的包名前缀。环境变量覆盖顺序应明确，不能直接将源项目 `override=True` 作为通用约定。
- 可复用的模型与客户端使用工厂或生命周期管理，避免每次请求重复加载。缓存范围、并发初始化和释放方式按运行环境设计；进程内单例不代表跨进程共享。
- 文本文件显式使用 UTF-8；使用 `Path` 组织路径。外部提供的路径在读写前校验解析结果位于允许目录内。

## 日志与错误

- 使用统一 logger。日志初始化避免重复 handler，按需配置级别和文件轮转；业务函数不自行配置全局日志。
- INFO 记录阶段与结果摘要，DEBUG 记录必要诊断，WARNING 记录可恢复异常，ERROR/exception 记录失败。带关联 ID、节点、耗时、数量；避免输出完整 Prompt、文档、向量和凭据。
- 基类已记录节点开始/结束时，子类只增加有业务意义的日志。
- 仅在能转换、处理或增加上下文的边界捕获异常；需要上抛时保留原始堆栈。对外错误和内部诊断分别处理。
- 降级行为必须说明结果类型、是否部分成功及调用方处理方式。失败不能被包装成普通成功消息。

## 验证与变更范围

- 使用已有 lint、类型检查和测试命令。没有工具配置时明确报告，不能声称已遵循不存在的 Ruff、mypy 或 pytest 门禁；添加工具属于单独的工程选择。
- 按风险验证空输入、字段缺失、错误类型、外部失败、返回形状和受影响调用方。网络/GPU 测试与无外部依赖的算法测试分开。
- 只读审查不改代码。修改保持当前公共契约，必要变更同步相关调用方、Spec 和测试。
