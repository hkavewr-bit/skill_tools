# 核心逻辑实体

输入：已确认 PRD、业务流程及现有 schema/迁移事实。使用[实体模板](../assets/templates/data-entities.md)，在原型和正式接口细化前统一对象、标识、字段含义与逻辑类型、必填/唯一约束、关系基数、状态迁移、所有权及生命周期。

以实际业务操作核对关系和约束；容量、重复操作、取消等规则须有需求依据。此阶段不锁定数据库引擎、SQL 类型、索引或接口地址。已有系统标明现状与拟变更，不能因设计新文档重建已有表。

定义归属：`数据实体.md` 维护业务含义、逻辑字段、关系和状态；总体设计分配负责模块；负责模块 Spec 定义物理存储、索引、事务及迁移。页面和 DTO 只写映射及特有约束，不复制状态机。后续发现实体变化按[变更规则](state-and-docs.md)处理。

无持久化对象时描述实际输入输出、事件及运行状态，不虚构表；持久化 Agent 会话仍需实体。小项目可将实体并入 `总体设计.md`，登记唯一位置。核心对象和业务约束无关键歧义、用户确认版本后进入概要方向及适用前端阶段。
