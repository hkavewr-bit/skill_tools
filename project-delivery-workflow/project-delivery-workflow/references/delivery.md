# 交付方式与部署资料

## 授权与交付方式（全阶段共用）

从会话及进度沿用已确认方式，首次登记依据。用户明确采用本工作流开始开发时，沿用“已有 Git/远程中为当前版本维护一个开发分支和一个 PR”的工作约定，每个已验证切片自动提交、推送和更新 PR；单纯自动匹配 Skill 或只读咨询不新增此授权。用户改为本地交付、暂不推送或暂不同步 Git 时，以具体限制为准，不重复询问或自动恢复同步。

- **Git/PR 模式**：检查 diff，只暂存当前范围文件；排除密钥、临时和无关内容。验证与文档同步后提交/推送同一版本分支，创建或更新同一 PR 的范围、验证和进度，核实远程包含目标提交。记录分支、commit、PR。禁止 `git add .`、强推、覆盖历史及自动合并。
- **本地模式**：提供可审阅的文件/差异和证据，最终更新指定目录或归档；进度登记 PR 本次不适用。暂不同步 Git 时不执行提交、推送或 PR 更新；仅禁止推送时保留已明确授权的本地操作。
- **失败**：缺仓库/远程/认证不是自动切换模式的理由；保留成果和准确错误，完成无依赖工作，报告仍未完成的交付步骤。本地 commit 不代表远程交付完成。

## 执行边界

按当前授权运行项目测试、构建及临时应用测试进程。Skill 本身不授权安装外部服务、社区依赖，或执行合并、发布、生产写入和实际部署。

本阶段只生成和检查资料，不运行部署 Compose、构建/拉取部署镜像、启动部署服务、执行初始化/迁移/seed 或部署冒烟。用户另行明确要求执行时，按新授权处理该动作，不把它归为资料检查。

## 部署资料

输入为本版本功能验收结论、运行约束、实际依赖、数据库结构和证据。产物放项目根目录或既有工程位置，只生成适用部分：

- `README.md`：范围、目录、环境/配置、开发/测试/部署命令、初始化/迁移、验证及排障、停止/升级、数据保留/备份/回滚。它是操作步骤的唯一入口，设计文档链接它。
- Dockerfile、忽略文件和无密钥配置示例；`docker-compose.prod.yml` 描述应用及可容器化依赖的网络、端口、卷、健康检查和启动依赖，不载入测试数据。
- 独立的 `docker-compose.test.yml`，包含适用的结构初始化和合成 seed 加载机制，数据与生产隔离。结构/迁移与 seed 分开，共用同一结构来源。
- 模型 API、托管服务、权重、GPU 等外部依赖的获取与配置要求，不声称已经安装或运行。

按实际镜像核对首次空卷初始化行为；已有库使用迁移，不承诺每次启动都重新执行 SQL。seed 可重复执行且不重复插入，测试账号注明用途。重置步骤限定测试资源并注明破坏范围/备份要求，不自动删卷或操作现有库。

## 资料检查与最终收尾

**资料检查 → 同步文档 → 按当前授权更新 PR 或本地交付包 → 记录最终版本与交付清单。**

1. 核对实际路径、构建上下文、变量、服务/健康检查引用、卷隔离、结构/seed 分离和 README 一致性。已有 Compose CLI 时核实帮助后用无秘密示例做只读配置解析；缺失时不安装 Docker，记录可做的静态检查及局限。
2. 同步受影响 README、设计、测试报告和进度；确认未变化的功能不重新验收。记录资料检查结果及剩余例外。
3. 执行上述授权交付方式；核实最终提交或归档实际包含新增资料及同步文档，不能引用收尾前的旧版本。归档只含交付范围，最终 SHA256 放包外清单或消息，避免自身哈希循环。
4. 给出最终版本、交付位置、文件清单入口和核验结果。更新、打包或核验失败时保留未完成状态。

分别报告功能验证、用户验收、资料交付、部署配置检查及部署运行状态。默认部署尚未执行；配置解析通过不能证明启动或业务运行成功。
