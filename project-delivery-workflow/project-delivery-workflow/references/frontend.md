# 前端排版、交互与规范

输入：已确认 PRD、流程、实体、目标设备和适用概要方向。沿用已选设计工具，默认 pen.dev；Figma/Pencil 等按用户选择。通过[工具协作](tools.md)核实可用能力与保存方式。无前端时登记不适用。

## 排版确认

先展示一个代表页面，再补齐当前版本页面与弹窗的低保真原型。评审页面入口、导航、信息区、字段、表单、按钮是否覆盖需求；记录节点到需求/实体的映射，计算与展示字段注明来源。示例数据不是业务承诺。

保存真实可编辑源、预览及版本到 `frontend/` 或已有指定位置，验证保存和渲染。已有确认设计直接复用。此步确认布局与操作入口；用户确认后再细化交互。

## 交互确认

在 `frontend/交互设计.md` 按主要场景记录：角色、触发/可用条件、字段校验、提交数据、成功反馈/跳转、失败恢复、权限差异，以及加载、空、失败状态；按适用性补取消、重复提交、流式停止/恢复。演练每个主要按钮的完整路径，关联原型节点和 PRD。

这里表达数据与行为需求，正式后端接口在架构/Spec 中确定。新增业务行为、字段或状态先同步上游并确认受影响内容；交互评审后进入规范提炼。

## 规范确认与交接

用[规范模板](../assets/templates/frontend-design.md)从已确认页面提炼公共视觉与交互规则，单页特例留在页面说明。低保真批准不代表颜色、字体等已批准；适用视觉规则仍未定时提供方案并确认，避免带着关键未决项定稿架构。

交接包含布局、交互、规范的确认版本、页面数据需求及评审处理结果。后台任务、异步处理、权限与 Agent 恢复等非页面能力仍由 PRD 驱动。
