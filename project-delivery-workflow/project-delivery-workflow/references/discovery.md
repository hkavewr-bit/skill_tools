# 业务流程与详细 PRD

## 业务阶段

输入：用户目标、现有材料及已有代码的事实。使用 brainstorming 与 grill-me，先确定目标用户、核心问题、当前版本成功标准和范围。已有仓库做只读了解；不能把代码现状等同于已批准的需求。

每轮集中一个决策点：参与角色、触发事件、主要步骤、业务分支、异常与完成结果。同步生成/更新可编辑业务流程图，并通过 Visual Companion 展示给用户；核对真实展示后再称可查看。

阶段产物为 `业务流程图.md` 与进度决定记录。用户确认当前图的版本后进入详细 PRD。此时图表达业务，不提前固定技术框架、数据库表或函数。

## PRD 阶段

基于已确认业务流程生成初稿，按业务模块进行多轮澄清。逐模块确认：

- 场景、角色、前置条件及用户目标；
- 正常步骤、分支、输入输出与业务规则；
- 权限、数据范围、错误/空结果/超时等异常行为；
- 优先级、当前版本边界、不做的内容；
- 可观察的验收标准，例如同一个上传重试不生成重复文档，而非“系统稳定”；
- 适用的延迟、规模、并发、成本与数据保留要求。

部署约束此时提前对齐：目标系统、资源/GPU、数据库和外部服务、网络可达性、已有基础设施。最终只交付部署资料，不实际部署。确定项目测试可用的服务/测试账号；缺失外部依赖不能用模拟成功代替真实联调。

Agent 项目在此阶段读 [效果评测](agent-evaluation.md)，对齐代表性用例、工具权限及评测标准。

## 结束条件

模块正常/异常流程、规则、边界和验收足够明确，关键未决问题已解决，即展示模块版本请用户确认。允许非当前版本需求明确延期，不把延期事项扩张成当前工作。

所有当前业务模块确认后，检查业务流程图与 PRD 是否一致，展示整份 PRD 的范围和关键决定进行终审。用户确认后进入前端分支或总体架构。PRD 重点回答做什么及如何验收，不设计函数实现。

## 一个问答示例

文档重传策略未定时，可围绕“同名且内容相同的文件再次上传，是否复用已有文档”提出一个问题，说明对重复数据与历史记录的影响。回复后同时更新业务规则、异常路径和验收标准，再进入下一个未决点。
