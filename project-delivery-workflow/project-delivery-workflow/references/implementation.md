# 功能流开发与模块验收

先核对入口的编码条件和实际版本。按当前功能流读取相关 Spec、需求及代码；后端参考存储、接口、规则和函数契约，前端参考原型、交互/视觉规范和字段映射，两端使用同一接口版本。

关键决定缺失或与代码冲突时，按[变更规则](state-and-docs.md)解决后再写依赖它的代码，其余已授权工作可继续。

## 开发中：完整功能流验证

业务切片是一个有入口、处理过程和可观察结果的完整可执行功能流，可横跨模块。一次实现该流程所需代码，然后从实际入口验证输出、状态或数据变化；按 Spec 覆盖该流程必要的失败分支，不按每个函数、类或文件拆测试。

优先复用现有流程测试，或使用接口请求、页面操作和简短脚本；不强制新增测试文件、逐函数单测或测试先行。主要函数契约用于指导实现和解释流程预期，不等于每个函数都要独立用例。验证只模拟内部调用、不经过实际功能链路时，不能称为完整流程已验证。

通过后同步受影响文档，按[交付方式](delivery.md)更新 PR 或本地成果，记录简洁证据即可继续同模块下一流程，不另设逐切片人工审批。失败先修复当前流程；不能把已知失败留到模块验收。代码和相关依赖未变且证据仍适用时，不重复运行；修复只回归受影响流程。

## 模块完成：按 Spec 测试验收

模块范围内功能流完成后，逐项对照 Spec 的验收标准，核对输入/前提、业务操作、输出/数据变化及规定的异常结果。复用开发中有效的流程证据，补齐缺失或受变更影响的场景。权限、状态、重复操作等按 Spec 融入完整场景，不铺开无关细节测试。

测试方式按场景选择自动化流程测试、接口验证或页面验收，不要求每条标准生成一个测试文件。构建、类型检查仅在对应改动需要时执行。

用[测试报告模板](../assets/templates/test-report.md)记录标准编号、实际结果、证据和残余项；修复未通过项并回归后，同步文档和交付版本，请用户对模块进行集中验收。等待模块验收时可整理证据或处理独立文档，不以启动新模块业务实现绕过门槛。跨模块流程注明主责模块和依赖，分别映射各模块标准，不重复执行同一有效用例。

## 阶段检查与整体验收

阶段所含模块验收后复核职责、依赖、公共契约和文档一致性，仅做有依据的必要重构；补测跨模块链路及本次调整影响的流程，不重跑未变化且证据有效的全部用例。公共行为变化按变更规则处理。

整体验收对照当前 PRD 及需求映射，复用模块验收结果，补齐尚未覆盖的跨模块完整链路，提交具体版本供用户整体确认。模块验收不能替代整体结论。

验证状态区分通过、失败、受阻、未执行、不适用；静态、模拟和真实集成分开记录。外部环境缺失时完成可行工作并标真实流程受阻，不能用模拟成功代替。必要验收项缺失时，只有用户明确接受例外才记有条件验收。Agent 项目另按[效果评测](agent-evaluation.md)核对 Spec 中的实际任务流；运行边界见[交付](delivery.md)。
