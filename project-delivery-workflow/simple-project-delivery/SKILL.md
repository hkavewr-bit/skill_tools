# 轻量项目交付

保留已确认需求，用简短工作卡、连续开发验证、一次交付完成任务。默认只读本文件，专项参考按需加载。

## 1. 快速定位

- 新项目确认目标、入口和运行方式；已有项目定向阅读相关入口、调用链、测试及用户改动。只有事实缺失或影响跨模块时扩大检索。
- 在回复中用几行写明：目标、修改范围、完成标准、必要假设。已有计划直接复用，不另建蓝图或 Spec。
- 用户已明确要求开发时直接推进。仅对影响范围、重大架构、安全或不可逆效果的未决问题提问，并继续不依赖答案的工作。用户明确要求先确认设计时遵守该要求。
- 新想法不自动插入当前范围，不静默删减已确认需求。

## 2. 连续开发验证

- 沿最短完整业务链逐步实现，尽早通过真实入口验证核心路径；不等待整个项目完成才联调。
- 连续推进已授权工作，不设置逐模块用户验收，不强制阶段状态机。
- 复用现有代码、规范和测试。按风险做针对性验证：涉及启动则检查启动，涉及业务规则则测规则，涉及权限或数据则测关键拒绝与失败路径。
- 复杂规则或 Bug 可在开发内部使用“失败测试→最小实现→通过→重构”；不为简单文案、配置或可逆低风险修改强制 TDD，也不依赖特定任务管理工具。
- 修复后重跑失败项和受影响检查；共享鉴权、契约、数据状态或基础设施变化才扩大回归。已有有效结果直接复用，无新变化或风险不重复全套验证。
- 环境或凭据不足时记录未验证范围，继续独立工作；替身通过不能证明真实集成可用。
- 收尾对变更及受影响边界做一次审查。功能错误、安全、数据完整性和承诺的契约问题必须修复；非阻断命名、抽象或可选性能建议记录为后续事项。

## 3. 一次交付

说明实现结果、实际验证命令与结果、剩余限制。满足完成标准后直接交付；用户要求正式验收时统一提交一次，修复反馈后可重新提交。

不默认生成 PRD、架构图、模块 Spec、独立测试报告或 Docker/Compose；用户需要时生成对应材料。已有使用说明或公开契约因改动失效时，只更新受影响部分。

## 上下文与恢复

- 短任务在对话中保留工作卡和证据即可。暂停、交接或上下文过长时，更新一份简短进度文件，优先复用项目现有文件，没有则用 `任务进度.md`。
- 只记录范围、当前结果、关键决定、相关路径、最近验证、阻塞及下一步，不粘贴全量日志。
- 恢复时先读进度与相关改动，不重新开展全项目分析；状态冲突以当前文件和运行证据为准。
- 不自动启动 handover 或维护第二份状态账本。已有 handover 管理的项目沿用其状态来源；用户另行要求交接时遵守其要求。
- 不默认组合多套技能或启动子代理。只有专项工作需要时才加载相应能力；不自动切换其他交付流程。

## 边界

遵守用户现有授权及仓库约束；不覆盖用户修改，不泄露密钥，不虚报验证。提交、推送、部署、付费调用和破坏性操作按已有授权处理；本流程不额外授予权限，也不对已授权动作重复索要确认。
