# 协作与技能接入

## 总 Skill 的责任

总 Skill 维护阶段、确认、文档和交接。专业 Skill 解决当前阶段的问题。不要同时启动两套完整交付流程。加载前发现真实可用的技能路径，读取说明，不把技能名当作已执行的工具。

这是用户选择本工作流后的流程约定，不能覆盖系统/开发者指令、工具权限或用户更新的指示。发现专业技能冲突时优先沿用用户已确认的定制顺序，说明实质差异；无法在现有权限内解决的冲突才询问。

## 按阶段接入

| 能力 | 何时使用 | 对接要求 |
|---|---|---|
| `superpowers:using-superpowers`、`superpowers:brainstorming` | 新项目需求探索 | 读取可用说明，复用已确认决策；Visual Companion 用于实时展示业务与架构方案 |
| `grill-me` | PRD、模块 Spec 存在未决内容 | 每次聚焦一个问题，按模块收敛；它负责需求追问，不负责绘图 |
| `diagram-builder` | 需要业务图、架构图、模块流程图 | 保留图源，依照用户选择在 Visual Companion 展示；负责表达，不另起一套需求采访 |
| pen.dev 对应可用连接器 | 有前端，进入页面设计 | 先排版，后交互；验证连接、文件保存和可编辑产物 |
| `superpowers:writing-plans` | 全部 Spec 确认并完成契约检查后 | 拆为业务切片；不提前写死实现，任务清单存项目进度，不另造重复状态 |
| 测试驱动、系统调试、代码审查、完成前验证技能 | 实施相应阶段 | 验证实际行为；复用既有规范；不把审查通过当用户验收 |
| `ui-ux-pro-max` | 前端排版/交互需要质量检查 | 可选辅助，仍用用户指定的设计工具 |
| GitNexus 影响分析、review | 已有代码且影响追踪有价值 | 绑定实际仓库与 worktree，核对索引新鲜度，图结果结合源码；小项目不强制安装 |
| MLflow 等效果评测技能 | Agent 项目且用户选择相应体系 | 可选；先说明依赖/成本，不能自动安装或接入追踪服务 |

必要技能未安装/不可读时，明确缺失及影响，并提出可审阅的替代；需要改变用户明确指定的交付形式时先获得同意。不要无限搜索或自动安装来修复环境。

## 特别的兼容约定

- 本流程设计产物统一在 `user_workspace/`。专业技能的默认 `docs/` 路径映射到这里，不并行维护两份 PRD。
- 用户已经选择浏览器可视化时，复用该同意，不重复询问“是否需要视觉辅助”。启动方式仍受工具权限限制。
- “所有模块 Spec”指本次约定交付版本的技术模块，包含在范围内的前端模块；未来版本只记录范围。
- 骨架先于详细 Spec：只提供已批准架构中的目录、入口、配置示例、依赖清单及测试框架。不能把骨架包装成已完成业务功能。
- 不因为专业技能建议而自动创建 worktree、并发实现所有模块或启动部署；按照用户范围和宿主执行规则选择。
- 此 Skill 不自动授权多 Agent。若用户/宿主允许委派，子任务继承同一确认基线、修改边界和文档约定，主执行者负责统一审查。
- 专业技能的提交、推送或发布建议不等于用户授权。保留现有修改，不为“重新测试”删除用户代码。

## 可视化交接

业务流程图/总体架构图使用一个可编辑来源（如 Markdown 中的 Mermaid，或单独图数据），浏览器预览从该来源生成。维护来源、预览、确认版本的对应，修改之后刷新并检查真实渲染，不能只因 HTTP 成功就声称图正确。

按语义确认更新图，不为每个语气词重绘。已确认/待确认/变化点用文字与视觉标识共同区分。图太复杂时拆成总图与模块图，保持到 PRD/Spec 的链接。

## 问答与收敛

问题结构：当前模块的一个未决点、必要背景、推荐做法与影响、一个问题。允许用户先自由描述；从回答提取决定，避免逐条朗读整份文档。

收敛条件：正常路径、异常路径、规则、权限、输入输出、范围、验收已足以判断实现，且没有影响本模块的关键未决项。非关键待办明确延期或标不适用。证据已充分的地方不凭空再造问题。
