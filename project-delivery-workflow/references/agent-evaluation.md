# Agent 项目的附加要求

本参考只在项目包含模型驱动的 Agent/RAG 等行为时加载，不强制采用某个框架。

## 需求与设计期

与用户对齐 Agent 的目标、输入输出、工具调用边界、需要人工确认的动作、状态与记忆、检索与证据引用、停止/超时/重试/恢复、成本与响应时间要求。

从真实场景构造合成或经授权的代表用例：成功、无法回答、检索无证据、工具失败、权限拒绝、多轮上下文和中断恢复。每个用例记录输入、预期结果/可接受范围、预期工具行为、不允许的结果、评分方法和通过标准。评测标准进入 PRD，实现方法进入模块 Spec。

不要只写“回答准确”。例如：资料不足时明确缺失依据；无授权时不调用写入工具；工具超时按已定义方式退出。成本上限和延迟标准由项目约束决定，不凭空承诺。

## 实施与回归

区分确定性代码检查与模型行为评测。能用规则判断的用规则；需要模型评分时说明标准、裁判模型与局限，并用用户标注样例校准。小样例试跑只能说明链路可用，不宣称统计可靠。

记录模型/提供商、提示词版本、检索配置或数据集版本、评分标准、采样设置、结果与成本。提示词、模型、工具或检索策略变化时回归相关代表样例，保留一个未用于反复调优的验收子集。

真实模型调用受成本、凭证和数据授权限制；没有环境时记录受阻，不能把模拟回复称为真实 Agent 评测结果。

## 可选工具

用户已选择 MLflow 或其他评测体系时，再发现并读取对应技能及依赖；介绍配套追踪、存储、模型调用成本。未选择时复用项目已有评测方式，不自动安装服务或把总 Skill 绑定到 MLflow。
