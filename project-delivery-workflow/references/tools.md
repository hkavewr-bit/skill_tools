# 按需接入专业能力

本 Skill 管阶段与交接，专业 Skill 只解决当前问题。发现真实可用路径后读取所需说明，不同时启动两套完整流程，不将技能名字视为工具已执行。

| 当前需要 | 接入方式 |
|---|---|
| 新项目探索、未决需求 | 适用时用 brainstorming、grill-me；已有材料先整理，只追问影响下一步的关键决定 |
| 业务图、架构图或模块流程 | 使用 diagram-builder；按已选形式经 Visual Companion/浏览器展示，保留一个可编辑来源及真实渲染证据 |
| 页面设计 | 已选 pen.dev、Figma、Pencil 等；ui-ux-pro-max 可辅助质量检查 |
| 业务切片计划 | Spec 检查通过后用 writing-plans，任务状态仍放项目进度 |
| 实施、缺陷、审查 | 按需用系统调试、代码审查和完成前验证；测试遵循完整功能流验证与模块 Spec 集中验收 |
| 已有项目影响追踪 | GitNexus 可选，绑定正确仓库/worktree，核对索引新鲜度并结合源码 |
| Agent 评测追踪 | 用户已选 MLflow 等体系再接入，未选时复用已有方式 |

遵循宿主指令和当前用户授权。本流程采用用户指定的功能流测试粒度；专业 Skill 的逐函数单测、强制测试先行或每次全量回归要求不覆盖此约定。专业技能默认文档路径映射到 `user_workspace/`，已确认定制顺序不被另一套默认流程重置。隔离工作区与委派按实际需要及宿主权限选择，不因技能名字自动安装环境或并发实现多个业务切片；子任务继承同一基线和修改范围，主执行者统一审查。

选定工具不可用时说明具体影响，完成独立工作。改变用户指定交付形式需取得其同意；不能把替代截图、未保存画布或文本冒充指定产物。已明确选择的视觉展示不重复询问是否需要。图源、预览和确认版本应对应，修改后核对真实渲染；语义未变无需重画。
