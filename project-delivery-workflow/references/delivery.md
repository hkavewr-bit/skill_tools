# 部署资料交付：不实际部署

输入：当前版本功能验收结论、部署约束、实际依赖清单、数据库结构及验证证据。

## 交付内容

- 项目根目录 `README.md`：目的/范围、实际目录、环境前提、配置项、开发与测试命令、部署步骤、数据库初始化/迁移、合成测试账号、验证方法、日志/排障、停止、升级及数据保留/备份/回滚注意项。
- 适用的 Dockerfile（前后端多应用按需多个）、忽略文件和无密钥配置示例。
- `docker-compose.prod.yml`：整个应用及可容器化的依赖，明确网络、端口、卷、健康检查及启动依赖；生产版不加载测试数据。
- `docker-compose.test.yml`：独立测试环境，具备适用的数据库结构初始化和合成测试数据自动加载机制，与生产数据隔离。
- 数据库结构/迁移脚本与测试数据脚本分开保存。关系数据库使用适合的 SQL；其他组件提供适用初始化方式。没有该组件时不凭空添加它。
- 外部模型 API、托管服务、模型权重和 GPU 等无法简单封装的依赖列出获取/配置要求，不把服务配置示例说成已部署依赖。

项目架构决定位置和启动方式。README 是部署操作入口，其他设计文档链接它，不重复维护另一套操作步骤。

## 数据初始化约定

生产与测试使用相同结构定义/迁移来源；测试另加合成 seed。按实际数据库镜像核实初始化机制及首次空卷触发条件。明确已有数据库通过迁移更新；不能承诺挂载 SQL 每次启动都执行。

测试数据生成可重复且不重复插入；合成账号注明仅供测试。重置测试数据的步骤明确限定测试资源；不自动删除数据卷或对现有库执行脚本。需要数据破坏操作时文档先标明影响与备份要求。

## 只读配置检查

检查文件和相对路径、构建上下文、环境变量、服务引用、依赖/健康检查、卷隔离、结构与 seed 分离，以及 README 与配置一致。

Compose CLI 已可用时，可针对无秘密的示例环境运行配置解析/校验（例如该版本支持的 `docker compose ... config --quiet`）；先核实本机帮助和参数。避免把展开后的真实密钥写入日志。CLI 不存在时不安装 Docker，执行可行的静态检查并写明局限。

本阶段不执行 `up`、`run`、镜像构建/拉取、数据库初始化/迁移/seed、服务启动或部署冒烟测试。用户明确另行请求执行时作为新授权单独规划，不归入本次资料交付。

## 结果陈述

分别记录功能测试结果、部署配置检查结果和“部署尚未执行，运行效果未验证”。未核实的步骤明确标记。不能用配置解析通过证明服务能启动，更不能把写好部署文档视为已上线。
